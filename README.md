# buildsync.ai

This is the official repo of buildsync.ai

The public marketing website of **BuildSync AI**, an AI workspace for engineering plans. The **homepage** (`/`) and the information pages (product, features, solutions, disciplines, learn, trust, legal, company, sign-up and log-in) are built. `/demo` and `/features/simulation` are not built yet.

## Development

Next.js (App Router) marketing site. Homepage lives in `app/(marketing)/page.tsx`.

```
npm install
npm run dev        # http://localhost:3000
npm run build      # production build
npm run typecheck  # TypeScript check only
```

Pricing slots read from `lib/site.ts` (`{{PRICE}}` until final). The workspace
previews are SVG stand-ins (`components/WorkspaceMock.tsx`) until the real
workspace screenshots / `<Workspace demo />` are available.

## Browser and device support

Built for phones, tablets, laptops and desktops (checked from 280px to 3840px wide), with mouse, touch and keyboard.

| Browser | Targeted |
|---|---|
| Chrome, Edge, Opera, Samsung Internet, Chrome for Android | current versions; the build targets back to Chrome 64 / Samsung 9 |
| Firefox, Firefox for Android | current versions; the build targets back to Firefox 67 |
| Safari on macOS, Safari and every browser on iPhone/iPad | the build targets back to Safari 12 / iOS 12. Full visual fidelity from Safari 14.1 / iOS 14.5; on older versions the content works but spacing is tighter because flex `gap` is not supported there |
| Internet Explorer, Opera Mini | not supported |

The minimum versions are declared in `browserslist` in `package.json`. The build uses that list to add the right CSS prefixes (including the iPhone ones) and to compile the JavaScript for those browsers, so keep it in step with this table.

Touch screens: menus open on tap and close on a second tap or a tap outside; hover effects are switched off (they would stick after a tap); tap targets grow to 44px; the compact header (hamburger) is used below 1320px wide. Also handled: dark-mode devices (the site stays light), reduced-motion settings, JavaScript switched off (all content still shows) and very narrow screens such as a folded Galaxy Fold (280px).

Fonts are served from this site (npm packages `@fontsource-variable/inter` and `@fontsource/ibm-plex-mono`, both OFL-licensed), not from Google, so the page never waits on a third-party font server.

How this was checked (October 2026): Chromium device emulation (24 device sizes, plus touch, mouse, keyboard, reduced-motion, dark-mode and no-JavaScript tests); a real WebKit engine (WebKitGTK 2.52: rendering at 15 widths and mouse/keyboard behaviour); a CSS feature audit against the `browserslist` versions; and a check that the compiled JavaScript is ES2018. **Not tested:** Firefox (not available in the test environment), real Safari and real iPhone/iPad/Android hardware, and the old minimum versions themselves (Chrome 64, Safari 12, ...): those rely on the compile targets and the CSS/JavaScript fallbacks, not on a test run. Test on real devices before launch.

## Not built yet

`/demo` and `/features/simulation` are not built yet, so links to them show a 404. Every other
link goes to an information page (`lib/pages.ts`) or to a homepage section: the header and
footer **Compare** and **Pricing** links jump to `/#compare` and `/#pricing`.
The newsletter, waitlist, search box, sign-up, log-in and contact forms are visual only
(nothing is sent; the forms say so when you press their button).
